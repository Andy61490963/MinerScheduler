# 正式挖礦與監控原始碼

本專案保留既有挖礦、風扇、溫度及啟停保護行為，依責任整理原始碼。正在運行的版本位於 `C:\test\CORE`，本專案的檢查與建置不會部署或重啟它。

| 目錄 | 維護內容 |
| --- | --- |
| `src/mining` | 啟動流程、礦工生命週期與程序保護。 |
| `src/safety` | 啟動核對、功耗保護與即時心跳。 |
| `src/hardware` | 台灣時段規則、顯卡讀值、風扇排程／監測與顯存節能。 |
| `src/coordination` | 本地模型忙碌暫停、閒置 60 秒恢復及人工停止優先。 |
| `src/dashboard` | 監控資料、開始／停止及設定保存流程。 |
| `web` | http://127.0.0.1:18776/ 的頁面、圖表與 LOG。 |
| `windows` | 一般使用者啟動、既有排程與 FanControl 整合。 |
| `config` | 整理當下的正式設定快照；不會隨網頁操作自動更新。 |
| `docs` | 現有操作說明。 |

離線檢查：

```powershell
& 'C:\test\CORE\TEST_環境\python.exe' -B 'C:\test\PROJECTS\CORE\project.py' check
```

組裝程式及設定至全新目錄；不啟動輸出、不搬移運行版本：

```powershell
& 'C:\test\CORE\TEST_環境\python.exe' -B 'C:\test\PROJECTS\CORE\project.py' build --output 'C:\test\建置\新版本'
```

需要完整發行檔時才加 `--with-dependencies`，它會唯讀核對並複製清單中的既有第三方依賴。預設建置不複製二進位檔，不帶入測試、狀態、人工停止標記、鎖檔、運行紀錄或舊的啟動證書；啟動證書應由原有核對流程重新產生。

來源檔案按功能命名，`project.json` 明確列出每個來源對應的原執行檔名。不要直接執行 `src`、`windows` 裡的單檔；它們保留既有相容匯入與正式路徑，應先建置並依原流程部署。本工具拒絕輸出至運行目錄、專案目錄或任何既有目錄，沒有自動部署功能。

日常調整功耗與風扇仍使用監控頁。`config` 是版本快照，未來安排版本更新時，必須重新整合當時的正式設定，避免覆蓋使用者後續調整；本次沒有把此快照寫回運行版本。

## 登入自動啟動

`windows/login.ps1` 是一般使用者登入的單一入口，建置為 `TEST_登入啟動.ps1`。它啟動風扇排程、監控頁背景與原有挖礦啟動核對。Windows 登入設定使用短命令呼叫此檔；不更改整台電腦的執行原則，不以系統管理員執行礦工，原有 SYSTEM 排程仍只負責功耗保護。人工停止標記存在時不自動恢復挖礦。

正常啟動與挖礦直接採用監控頁保存的日間／離峰功耗，不再先以150W挖礦一分鐘。初始化核對及啟動證書亦使用保存的時段設定；一分鐘負載觀察只更新狀態及顯存節能。150W與900MHz僅作保護初始化、風扇切換、禁止挖礦、停止或異常時的安全基準。核心80°C、熱點105°C或顯存90°C會降瓦，核心82°C或感測失效會停止；溫控不因移除起始150W而停用。日常值以網頁為準，更新時必須保留使用者最新設定。

監控網站固定為 http://127.0.0.1:18776/ ，伺服器明確使用 `--port 18776`。登入入口先啟動網站，再處理風扇及挖礦，因此人工停挖或風扇初始化時仍能開啟網站查看 LOG、按開始或停止。關閉瀏覽器不會關閉網站或停止礦工。
